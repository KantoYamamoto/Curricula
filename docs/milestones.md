# マイルストーン案 v0.3

> 実装開始後の状態：2026-09-28に初回増分を実装。以下はv0.3時点の計画であり、現在の確認範囲は[初回レビュー](reviews/pilot-0.1.0.md)を参照。

更新日: 2026-09-28 / 状態: 改訂可能な計画。実装未着手。

範囲は比例と小学校までの関連前提。高校・大学・人文・語学の少数例を構造検証に使う。データをAPI経由で構造表示と教科書風の閲覧ページに届ける。粒度や関係を事前に全面確定せず、調査・実装・レビューを往復する。専門家の確保を当面の工程や完了条件にしない。

## M0 — 原典と最初の小標本

成果物: 対象原典の取得版、比例の一つの能力・知識・原典対応・前提、閲覧時の期待結果。

- 原典・訂正・コード表・LODの対象項目を照合する。
- 教科書の公開資料で章節・到達内容の区切りを調べ、独自の分解理由を残す。
- [対象範囲](pilot-scope.md)に従い、最初は正の数量の例を選ぶ。
- 比例だけの収録を、反比例も含む原典の完全対応としない。

全対象の調査完了を待たず、照合済みの小標本からM1/M2へ進む。未照合の範囲は明示する。

## M1 — 最小モデルと交換契約を試す

成果物: 小標本のSwift記述案・JSON案・章節の参照案。

- 原典、枠組み、知識、能力、関係、閲覧順を分ける。
- 安定ID、版、出典、部分対応、条件の最小仕様を採る。
- [構造検証例](architecture-cases.md)を使い、大学・異分野を不適切な必須属性で排除していないか確認する。
- 分類・関係の迷いは具体例を調査して改訂する。全面的な分類の完成は要求しない。

最初の小標本をレビューし、実装中もM1へ戻れるよう判断理由を残す。

## M2 — 一つの節を画面まで通す

成果物: Swift宣言→検証→JSON→ローカルAPI→構造表示／閲覧ページ。

- 一つの対象について両画面が同じAPIとデータ版を使う。
- ID重複、参照切れ、関係の型違反を検出する。
- 原文と説明、部分対応、前提の文脈、出典を表示できる。
- 章節の並べ替えで対象IDや原典階層が変わらない。
- データ取得失敗・未調査・該当なしを区別する。

[閲覧・API仕様](viewer-api.md)に基づき、この増分をレビューする。

## M3 — 対象内容と境界例を増やす

成果物: 正の数量→符号・座標→小学校までの関連前提、の順に追加したデータと閲覧内容。

- [対象範囲](pilot-scope.md)の停止条件を適用し、全算数の整備へ拡散させない。
- 能力の条件・達成例・境界例、前提ごとの根拠を確認する。
- 原典の階層や教科書の掲載順を、そのまま必須前提にしない。
- 文脈に応じた必須前提の循環を検出し、一般的な関連の循環は許す。
- 高校・大学・異分野の検証例を実行可能な検証へ移す。
- 各増分をレビューし、未収録・未調査・既知の限界を残す。

レビュー担当の専門性を仮定しない。確認者と観点を記録し、特定資格のレビューを完了条件にしない。

## M4 — ローカルMVPを評価する

成果物: 再現手順、二つの画面による利用結果、改訂の実例、既知の限界。

- 対象→能力→原典、条件付きの前提をAPIと画面でたどれる。
- Swift・JSON・API・画面の内容と版が一致する。
- 分割・統合・訂正を一例実施し、旧版と移行先を確認する。
- 学年・文科省コードが非該当のデータを不正扱いしない。
- 記述負担、診断、ビルド時間、閲覧しやすさ、レビューの負担を記録する。
- 段階的レビューで見つかった重大な不整合を解消し、残る限界を示す。

Swift、分類、粒度、対象範囲、表示構成を結果に基づき再検討する。専門家レビューの追加は要求しない。

## M5 — 公開と次の収録範囲

公開先、コード・データのライセンス、対応環境、外部向けAPI、更新運用を検討する。教材本文・問題演習・学習記録を追加するかは別判断とする。
