## 設計中の指摘と対応

1. macOSでは大文字小文字だけが異なるSwiftターゲットのディレクトリが衝突した。実行ターゲットを `CurriculaCLI` に分離し、ビルド・テスト成功を確認。
2. 前提が未登録の能力を基礎到達と誤認しないため、初回の全能力に `uninvestigated` を明示。
3. 画面の対象リンクに内部IDが露出していたため、APIでラベルを取得して表示。IDは詳細へ残す。
4. ブランドリンクも選択中のデータ版を維持するよう修正。
5. 原典項目の自動再取り込みが独自能力を上書きしないよう、入力JSONを別資源へ分離。インポートコマンドは新規候補ファイルにのみ書き出す。

## 次の増分

1. T03/M0：4項目の本文・訂正票・LOD照合と親階層の取り込み。出典メタデータに適用期間・訂正履歴・資料種別を追加する。
2. T08/M3：乗法・倍・表・座標などの前提経路を原典へ対応付け、停止条件を満たす境界と未調査を分ける。
3. T01/T02：A04/A06/A08/A11の不足例を追加し、履修規則の端点とAND/ORの必要性を見直す。
4. T05/M4：分割/統合・定義変更の版と移行表を実装し、旧版を再現する。
5. T06：ユーザーが二つの画面で粒度・条件・対応の読みやすさを確認し、指摘を次版へ反映する。

専門家の確保は当面の条件としない。確認範囲の小ささから、全分野・全教育段階への対応を主張しない。
