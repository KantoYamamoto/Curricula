本格的な収録範囲を増やす前に、少数の境界例をSwift・JSONで表現する。以下の大学の能力文や架空の課程は設計用の合成例で、特定の大学の実際の到達目標を引用したものではない。実データと識別できるよう `synthetic` 等の出典種別を付ける案。

大学教養について、人文・社会・語学と理数のどちらにも広げられるか検討する。いずれかの分野へ今固定しない。

| ID | 入力例 | 期待結果・破綻を検出する条件 |
|---|---|---|
| A01 | 同じ比例関係を小6・中1の原典へ対応付ける | SubjectMatterを学年ごとに強制複製しない。枠組みと能力の条件は残す |
| A02 | 正の数量の表を読む能力と、負の座標を含むグラフを読む能力 | 同じ対象でも能力・条件を区別。片方の証拠だけで同等とは推論しない |
| A03 | 高校の関数を調べる例と、大学の写像・線形写像を扱う例 | 対象の一般化・制限を関係で記述。「比例」「一次関数」「線形写像」を名前の近さだけで統合しない |
| A04 | 架空大学A/Bが同じ知識を異なる年度・課程で扱う | 機関・年度を区別。大学の項目に文科省コードや固定学年を要求しない |
| A05 | A大学の必修の履修順と、B大学の異なる学習経路 | 履修規則を世界共通の学習前提へ自動変換しない |
| A06 | 学会の参照基準と、大学の授業シラバス | 資料種別・発行主体・適用範囲を保持。同じ権威や法的効力と扱わない |
| A07 | 同じ用語に異なる定義域・仮定を持つ記述 | 意味が異なる対象を別IDにできる。条件を消して同値と判断しない |
| A08 | 自然科学のモデルの近似条件と、数学上の定理の成立条件 | いずれも条件を記録。科学のモデルを無条件に真の定理へ変換しない |
| A09 | ある歴史事象への異なる解釈と、その根拠・批判 | 複数の立場を出典付きで併記できる。片方を勝手に真とせず、併存を参照エラー扱いしない |
| A10 | 語学で相手・目的に応じた説明を行う能力 | 一つの正解文字列や自動採点を要求せず、行動・条件・観察基準を保持 |
| A11 | 原典の広い態度目標に、観察可能な能力が部分対応する | 原典を保存し、完全な測定可能性を偽装しない |
| A12 | 新しい原典で項目が分割される／科目の分類が変わる | 旧原典・旧対応を再現し、新旧の対応を根拠付きで保持 |
| A13 | 根拠の異なる必須前提・推奨・代替経路 | 文脈ごとに検証。全関係を一律DAG化せず、未対応のAND/ORを単純辺へ欠落変換しない |
| A14 | コード表の更新と、学問上の知識の定義変更 | 前者だけで知識IDを変えない。後者の意味変更は版・移行として扱う |

A03の数学的な区別の例: 実数上の `f(x)=ax` は線形写像の例として扱えるが、`f(x)=ax+b`（b≠0）を同じ意味の線形写像として統合しない。学校で使う呼称と大学での定義・条件の違いを表せるか検証する。具体的な分類・対応は資料を調べて段階的にレビューする。

## M1での合格条件案

1. 全例について、対応する要素・関係・文脈・出典の配置を説明できる。
2. A01〜A07、A12〜A14は最小のデータ例を記述し、JSONで意味を失わず出力できる設計を示す。
3. A08〜A11は、数学専用の必須条件によって記述不能にならないことを確認する。汎用採点や推論の実装は要求しない。
4. 表現できない項目は「未対応」として明記し、支持済みと見せない。将来その項目を追加する際、何が変更されるかを記す。
5. 原典と条件・観点の対応を記録し、根拠が原典外なら信頼できる資料へ遡る。確認範囲と残ったモデル上の不足を具体的に示す。
