# データ構造を確かめる小標本と補助ケース

更新日：2026-09-28。構造を確かめるためのレパートリーを増やすという依頼への増分。教材の網羅ではなく、意味が異なるデータを混同せず保持・取得できるかを確認する。

主たる検証は[実際の学習指導要領を使った8教科・11例](cross-subject-validation.md)。以下のA01〜A14は、改訂や機関別経路などを意図的に作るための補助ケースとする。

## 再現方法

```sh
make export
make check
make serve
```

[構造検証用の目次](http://127.0.0.1:8000/read?release=examples-0.1.0)と[改訂例](http://127.0.0.1:8000/read?release=examples-0.2.0)を開ける。データ版の選択でも切替可能。版を切り替えた際は、その版の最初の節に戻り、別版で存在しない節やIDを引き継がない。

| データ版 | 用途 |
|---|---|
| cross-subject-0.1.0 | 国語・理科・社会・外国語・音楽・道徳・算数・情報。実原典69項目、11節。初期表示 |
| pilot-0.1.0 | 初回の比例教材小標本。公開済みのファイルは変更しない |
| examples-0.1.0 | 比例の実原典4項目＋学校・大学・科学・歴史・語学の合成例。6節 |
| examples-0.2.0 | 合成項目の分割・架空機関コードの変更・定義変更の候補。7節。スキーマ版は0.1.0のまま |

補助データは [StructureSamples.swift](../Sources/CurriculaPilot/StructureSamples.swift)。架空機関・学習経路は合成例と表示する。理想気体と線形写像の根拠は[参照資料](cross-subject-validation.md#根拠の扱い)およびデータの編集理由に記録する。

## 不正例と不足を検出する例

[StructureSamplesTests.swift](../Tests/CurriculaTests/StructureSamplesTests.swift)でA01〜A14を個別テストとして対応付ける。全ての正常例をJSONに書き戻し、参照と条件・分類・対応範囲が残るか検証する。既存の[検証テスト](../Tests/CurriculaTests/CurriculaTests.swift)も維持する。

- A大学とB大学の逆方向の必須前提を同じ文脈へ移すと、循環として拒否される。
- 履修規則を誤って学習前提へ変えると、今回の例では循環が顕在化する。
- 態度目標の対象外範囲を残したまま完全対応に変えると、矛盾として拒否される。
- A06の合成資料は、現SourceDocumentへ直接デコードできないことを期待結果にする。このテストの成功は「資料を取り込めた」ことを意味しない。
- A13の代替経路は未対応として拒否し、AND/ORの元のまとまりを検証資源へ残す。
- A12/A14の改訂対応候補は実在する旧新版のIDと理由を持つが、現行JSON契約に含まれていないことも確認する。

[unsupported.json](../Tests/CurriculaTests/Fixtures/unsupported.json)は不足を検討するための**契約外の候補入力**であり、公開APIが対応済みの仕様ではない。A06の資料を実在の出典としてDBへ投入したり、A12/A14の候補を証明済みの同値対応と扱ったりしない。対応機能を実装したら、期待された失敗のテストを成功例へ置き換え、スキーマ版とレビュー記録を更新する。

## 小標本から分かった変更候補

1. SourceDocumentは公式CSVの取得情報に寄りすぎている。資料種別・由来・適用範囲を持たせ、告示・取得・生成の違いを表現する。非該当と未調査を区別できる仕様が必要。
2. 版付きファイルだけでは「なぜ分割したか」「どの旧項目から移ったか」を交換できない。対象版・ID・種類・理由・未対応範囲を持つ改訂対応を契約化する必要がある。
3. 単純な前提辺ではORとANDの組合せを表せない。能力集合をまとめた経路・条件式の導入を検討する。
4. 履修規則を能力間で仮表現する現状には限界がある。コースや単位の管理を始める場合は別モデルが必要。

これらは[DB移行方針](database-editing-plan.md)へ引き継ぐ検討事項であり、DBを置くだけでは解消しない。今回は実データの大規模追加やDB実装へ広げず、再現可能な小標本として問題を残す。
