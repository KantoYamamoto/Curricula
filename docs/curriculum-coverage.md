## 収録範囲

文部科学省の[現行コード表一覧](https://www.mext.go.jp/a_menu/other/data_00001.htm)で確認した、平成29年告示の小学校82V12・中学校83V11を対象とする。総則、各教科の共通見出し、各教科の全項目、特別の教科道徳、外国語活動、総合的な学習の時間、特別活動、小学校国語の学年別漢字配当表を含む。漢字配当表の1,026字も個別項目として保持する。

コード表には前文のコードがないため、[文科省の本文PDF](https://www.mext.go.jp/a_menu/shotou/new-cs/1384661.htm)から前文を補った。小学校本文15–16頁（PDF17–18頁）、中学校本文17–18頁（PDF19–20頁）。柱・ページ番号・ルビを除き、段落内の改行を接続し、ページ画像と照合した。コードを作り足さず、PDFの位置を出典に記録する。

対象は通常の小学校・中学校の上記指導要領。幼稚園、特別支援学校、高等学校、指導要領解説、移行措置、PDFに付録として収められた法令・別校種の文書は、この収録完了の集計に含めない。

## 区切りと順序

原文は学校段階 → 掲載された教科・領域 → 共通項目・学年帯・分野で138区切りに分けた。学年別漢字配当表は別の見出しと6学年の区切りを設ける。各区切りの中は公式CSVのNo.順を保持する。親項目が別区切りにある場合もUUIDで参照できる。

小学校国語第1・2学年の「読むこと」（Ｃ見出し、内容の6項目、言語活動の3項目と小見出し、計12原文）を確認した。6つの学ぶ対象と目標に分け、各目標の観点を注釈として残した。言語活動は条件の根拠に結び付ける。**次は同じ学年帯の「話すこと・聞くこと」**。教科の共通目標・取扱いを確認し、知識・技能、話すこと・聞くこと、書くこと、読むことのまとまりから、学ぶ対象と目標を整理する。その後に第3・4学年、第5・6学年と進める。教科は指導要領掲載順で小学校を進め、続いて中学校を進める。道徳・活動の目標と取扱いも別途整理する。

前提の関係を指導要領の掲載順から作らない。根拠がある前提・推奨経路だけを別の構造で記録する。目標は自動判定の可否に関係なく残し、判定のための観点がある場合は自然言語の注釈にする。自動評価器がない観点をソフトウェアによる評価済みと表示しない。

## 台帳の更新

台帳の各区切りにUUID、順序、学校段階、教科、公開版、目次・節UUID、原文UUID集合、原文の期待件数・実際の件数、目標整理の状態を記録する。APIは `/api/v1/coverage`。

- 原文の `complete` は、公式CSV全行と補足前文が一度ずつ入り、本文・件数・順序・出典・参照を検証できた場合。
- 目標の `pending` は未着手。`inProgress` は一部整理。`complete` は区切り全体を確認し、`reviewedOriginalIDs` に全原文UUIDを記録した場合。
- 作成した目標・注釈のUUIDを `goalIDs`・`annotationIDs` に記録し、対応する公開版・根拠からたどれるようにする。本文中の目標見出しや小標本があるだけでは完了にしない。
- 編集内容はSQLiteの下書きと不変の改訂に保存し、区切りごとに新しい公開版を作成する。原文版と過去の台帳はGitで保持する。確認記録はSQLiteの `work_reviews` に不変のUUIDで保存する。記録は公開版と確認した原文UUID・目標UUID・注釈UUIDへ固定し、原文台帳へ重ねてAPIと画面に表示する。更新時は直前の確認記録UUIDを照合し、競合を拒否する。DBから公開版を `data/authoring`、確認記録を `data/work-reviews` へ書き出すと、閲覧専用起動でも同じ進捗を再現できる。

## 出典・階層・識別子

公式CSVは [`data/sources/mext`](../data/sources/mext) に配布時のバイトのまま保存し、取得日、版、URL、SHA-256を記録した。本文は一切短縮せず、画面の見出しだけを短くする場合がある。原文の根拠は本文ごとに引用位置と出典の改訂UUIDで固定している。

階層・学年・分野の補助情報には教育データプラス研究会の[学習指導要領LOD](https://jp-cos.github.io/)を使用し、82・83の全コードに対応する情報を [`metadata.json`](../data/sources/mext/metadata.json) に抽出した。利用条件はCC BY 4.0。取得した元データのURL・ハッシュと変更箇所を保持する。本文はLODからではなく公式CSVから取り込む。

コードの前方一致を親の判定に使わない。道徳の学年帯や外国語の分野などには親子でコードの異なる桁がある。また、LODの章をまたぐ親関係9件は公式PDF目次と照合して外し、各章を同じ深さに置いた。総則や各教科の章を他章の親にしない。未指定の学年を「全学年」に置き換えず、明示された複数学年だけを配列に保存する。

既存小標本に同じ原典コードがある場合は既存UUIDを引き継ぐ。新規原典のIDは固定名前空間と原典コードからUUID v5を割り当て、コードは `externalIDs` と `aliases` の別索引に置く。編集版UUIDはIDと内容から生成し、内容が変わると別版になる。原典コードの変更・分割・統合は将来の対応表と変更履歴で扱い、意味が同じという推測でIDを付け替えない。独自の目標・分割・統合には既存のUUID v4による編集操作を使う。

## 再生成と検証

```sh
make export-curriculum  # 固定した入力から生成。ネット接続不要。
make check             # 全行照合、章・学年帯・漢字、SQLite、API、出力の再現性
make serve-edit         # 原文版を追加投入し、収録状況・閲覧・既存のローカル編集を起動
```

原典の補助メタデータの再抽出は `scripts/extract_curriculum_metadata.py` で、取得版の2ファイルを `--items`・`--hierarchy` に指定し、別の `--output` へ書き出して同梱ファイルと照合できる。通常の生成ではこれらの大きな元TTL・PDFは不要。前文は画像確認済みの抽出結果を固定している。

一つの節に属する原文を一括取得する `/api/v1/releases/:release/reading-sections/:id` を追加した。既存の項目単位APIも保持する。[HTTP API仕様](viewer-api.md)を参照。公開済みDBの版は不変なので、閲覧時は選択した版の索引をキャッシュする。新しく公開した版の一覧はDBから読み取り、全版の全項目を毎回読み直さない。
